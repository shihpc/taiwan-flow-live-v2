## 這份文件的作用

盤點四站 30 個 tab、找出哪些指標藏有 alpha，本質是**搜尋**而非驗證。搜尋比驗證危險：
會看遍所有結果再挑最好的，「挑」這個動作本身就製造假陽性。

所以候選清單、指標定義、判準門檻**必須在跑之前寫死並 commit**。跑完之後不回頭改定義、
不追加候選、不調門檻。結果難看也照實報。

**這份文件的 commit 時間戳必須早於掃描結果的 commit 時間戳**——這是唯一能證明「先註冊後測」
的憑據，git log 可查。

## 1. 方法

### 1.1 樣本與過濾（沿用既有回測，不重新發明）

| 項目 | 設定 | 來源 |
|---|---|---|
| 期間 | 快取涵蓋的全部交易日 | `backtest/fetch.py` |
| 流動性 | 當日成交額 ≥ 1 億 | `LIQ = 1e8`，`run_sorting.py:15` |
| 排除 | ETF（代號 `00` 開頭）、`_TAIEX` | `run_sorting.py:59` |
| 報酬 | 收盤對收盤，未除權息調整 | 同既有 7 項 |
| 對照組 | 同流動性、`surge < 1.2 或 \|ret\| < 1%`（明確無訊號） | `run.py:145` |

### 1.2 主要結果變數

**T+3 對 TAIEX 超額（`e3`）為唯一主要指標。**

理由：與既有 7 項一致，可直接橫向比較。T+1（`e1`）只作描述用途、**不列入採用判準**——
每多一個判準期別就等於把檢定次數翻倍，這是最容易偷渡假陽性的地方。

### 1.3 為什麼不報 p 值

stock-day 樣本**同一天內高度相關**（大盤一動全體同向），把它們當獨立樣本算 p 值會把顯著性
灌到離譜。這不是保守，是算錯。

改用兩層判準：

**第一層（效果量，pooled）**：訊號組的 `e3` 平均，與對照組比較。

**第二層（日層級，處理橫斷面相關）**：把每個訊號日的訊號股 `e3` 先取當日平均，
得到一條「逐日平均超額」序列（N ≈ 交易日數，日與日之間接近獨立）。報：
- 逐日平均超額的平均
- 正報酬日佔比

第二層是用來擋「單一天大暴衝拉高整體平均」——pooled 平均看不出這件事，日層級看得出來。

### 1.4 切半驗證

交易日清單**依索引對半切**（前半／後半），不指定日期——由程式在執行時計算，
避免我挑一個好看的切點。

**存活定義：`e3` 平均在前後兩段同號，且兩段各自 N ≥ 200。**

同號要求是刻意設的強條件。一個只在半段有效的訊號，最可能的解釋是過擬合或單一市況產物，
不是穩定 alpha。

### 1.5 採用門檻（先訂）

| 判準 | 門檻 |
|---|---|
| 全期 N | ≥ 500 |
| 前後半各自 N | ≥ 200 |
| 全期 \|e3 平均\| | ≥ 0.50% |
| 切半同號 | 必須 |
| 逐日平均超額與 pooled 同號 | 必須 |

0.50% 的來源：既有回測的錨點——湧入訊號基準 −0.51%、土洋同買 +0.55%
（`backtest/report_indicators.md:21,28`）。低於這個量級的訊號，即使統計上活著，
做成卡也沒有實際區辨力。

### 1.6 結果分三層報告

| 層級 | 條件 | 後續 |
|---|---|---|
| **A. 存活** | 全部門檻通過 | 候選做卡，但仍需單獨複驗 |
| **B. 半段活** | 效果量夠但切半不同號 | 明列為疑似過擬合，**不做卡** |
| **C. 陰性** | 未達效果量門檻 | 照實列出 |

**C 層一定完整寫進報告。** 只報跑贏的，報告本身就是挑選偏差的產物——
那比沒做這次盤點更糟，因為它看起來像證據。

### 1.7 多重比較揭露

報告開頭固定一行：

> 本次共檢定 K 個訊號。若全部為無效訊號，在名目 5% 水準下預期仍有約 0.05K 個
> 會偶然「看起來有效」。請據此對 A 層結果打折。

K 由候選清單長度自動帶入，不手填。

- 重抓要**整批刪** `backtest/cache/price_*.json.gz`：`fetch.py` 的續傳是逐檔跳過
  （`if pf.exists() and inf.exists(): continue`），只刪一部分會留下「一半有欄一半沒有」
  的混合快取。掃描程式的閘門（`cache_has_volume`）對混合快取一律不放行——
  **整批不跑**，而不是靜默漏算缺欄的那幾天再照常印報告。
- 報告必須印出快取 volume 的實際涵蓋日數與起訖日，讓讀者看得出跑的是哪一段。

### 6.4 清單凍結

以上 2 列（K_TESTS_P2 = 3）即為第二階段全部候選。第二階段掃描跑完後不得增刪，
結果報告必須逐項對得上——**不得有「跑了但沒報」的訊號**（同 §2.5）。

§2.3 表中的第三列（postmkt 當沖比率）**仍未解鎖**：它另需 `TaiwanStockDayTrading`
資料集，快取沒有，本階段不列入候選、不計入 K。
